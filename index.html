路由约定

// mocks/ 目录 → 路由表

📁 目录 ↦ URL

mocks/
├── users/
│   ├── GET.json          →  GET    /users
│   ├── POST.json         →  POST   /users
│   └── {id}/
│       ├── GET.json       →  GET    /users/{id}
│       ├── DELETE.json    →  DELETE /users/{id}
│       └── orders/
│           └── GET.json   →  GET    /users/{id}/orders
└── posts/
    ├── GET.json          →  GET  /posts
    ├── POST.json         →  POST /posts
    └── {postId}/
        └── comments/
            └── GET.json  →  GET /posts/{postId}/comments

规则就是：文件名 <METHOD>.json → 方法；目录名 → URL 段；{xxx} 路径参数。

📝 响应模板：以 _ 开头的都是指令

{
  "_status":    201,                  // 自定义 HTTP 状态码，默认 200
  "_headers":   {"Location": "/users/42"}, // 额外响应头
  "_delay_ms":  300,                  // 延迟多少毫秒再回

  "id":   42,                       // ← 实际响应 body
  "name": "newbie"
}

_status / _headers / _delay_ms 这三个是已知指令，其它任何 _xxx 字段也会被剥掉（保留给将来扩展）。

为什么用它

// 8 个常见痛点 & 一个共同答案
🌱

零配置

默认 ./mocks、端口 7777，扫一下目录就起服务。

📦

零依赖

只使用 Python 标准库，BaseHTTPRequestHandler + ThreadingHTTPServer。

🐢

延迟注入

_delay_ms 让响应变慢；CLI -d 全局再叠加一层。

💥

错误注入

_status 模拟 4xx/5xx；_headers 注入自定义响应头。

🌐

CORS 默认开

任意 Origin 放行、OPTIONS 预检直接过 —— 前端 fetch 不用配代理。

🧬

路径参数

{id} / {postId} 这种约定就支持任意位置、任意深度的路径参数。

🧵

多线程

每个请求独立线程，并发抓取/批跑不互相阻塞。

🧪

附 6 项 smoke test

子进程启服务 → urllib 验证 → 关服务，全程零额外依赖。

安装与使用

// 三种姿势
# 方式 1：直接下载单文件（推荐，本工具就一个 .py）
curl -O https://raw.githubusercontent.com/1fzx23/mocklite/main/mocklite.py
python mocklite.py --help

# 方式 2：克隆仓库（自带示例 fixtures）
git clone https://github.com/1fzx23/mocklite.git
cd mocklite
python mocklite.py

# 方式 3：pip install（会注册一个 mocklite 命令）
pip install .
mocklite
# 指定 mocks 目录 + 端口 + 全局 100ms 延迟
python mocklite.py ./fixtures -p 8080 -d 100

# 想让同事也能访问，绑定到 0.0.0.0
python mocklite.py ./mocks --host 0.0.0.0 -p 9000
